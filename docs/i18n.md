# Internacionalización

Cómo funciona el sistema de traducciones y cómo añadir o modificar contenido bilingüe.

---

## 1. Locales soportados

- `es` — Español (default)
- `en` — Inglés

El routing es **manual (file-based)**: cada locale tiene su carpeta en `src/pages/`. **No hay bloque `i18n` en `astro.config.mjs`** (se eliminó porque su middleware 404eaba `/es/`). `/` redirige a `/es/` mediante meta-refresh en `src/pages/index.astro` (solución provisional hasta que se decida un hosting con redirects nativos).

| Locale | URL |
|--------|-----|
| `es` | `/es/` (y `/` redirige aquí) |
| `en` | `/en/` |

## 3. Helpers (`src/i18n/index.ts`)

```ts
import es from './es.json';
import en from './en.json';

export type Locale = 'es' | 'en';
export type Translations = typeof es;

const translations: Record<Locale, Translations> = { es, en };

export function getTranslations(locale: string): Translations { ... }
export function getLocaleFromUrl(url: URL): Locale { ... }
export function getRelativeUrl(url: URL, targetLocale: Locale): string { ... }
```

- `getTranslations(locale)`: devuelve el diccionario. Si el locale no es `en`, devuelve `es` (fallback seguro).
- `getLocaleFromUrl(url)`: lee el primer segmento del path. Si es `en` → `'en'`, en otro caso → `'es'`.
- `getRelativeUrl(url, targetLocale)`: traduce la URL actual al otro idioma, preservando el subpath.

## 4. Patrón de uso en componentes

```astro
---
import { getTranslations, getLocaleFromUrl } from '../i18n';

const locale = getLocaleFromUrl(Astro.url);
const t = getTranslations(locale);
---

<h1>{t.hero.name}</h1>
```

No se importa `Astro.currentLocale` ni se usa `Astro.site`. Se trabaja siempre con la URL parseada para mantener consistencia entre el servidor (build estático) y el cliente.

---

## 5. Cambio de idioma (`LangSwitcher`)

`src/components/LangSwitcher.astro` muestra `ES | EN`. Para cada opción calcula `getRelativeUrl(Astro.url, '<locale>')` y enlaza a esa URL.

Como el `<ClientRouter />` está activo, el cambio de idioma es navegación SPA: los scripts se re-inicializan automáticamente (ver `docs/architecture.md`).

## 6. Reglas al traducir

1. **Mantener claves idénticas**: cualquier cambio en `es.json` debe replicarse en `en.json` en la misma revisión.
2. **No hardcodear strings en `.astro`**: todo lo visible va al diccionario.
3. **Plurales y condicionales**: si un valor cambia por género/número, crear claves separadas (`viewProject` / `viewCode`). Aún no hay casos de pluralización compleja.
4. **HTML en strings**: los diccionarios son texto plano. Si necesitas HTML seguro, mejor componente condicional que `set:html`.
5. **Emojis / iconos**: si van dentro de un texto traducible, asegúrate de que el contexto cultural los soporte. Los iconos SVG del layout viven en `.astro`, no en JSON.

## 7. Añadir un nuevo locale (receta)

1. **Diccionario**: copiar `src/i18n/en.json` a `src/i18n/<codigo>.json` y traducir.
2. **Tipo y registro** en `src/i18n/index.ts`:
   ```ts
   import fr from './fr.json';
   export type Locale = 'es' | 'en' | 'fr';
   const translations = { es, en, fr };
   ```
   Actualizar `getTranslations`, `getLocaleFromUrl` y `getRelativeUrl`.
3. **Página**: crear `src/pages/<codigo>/index.astro` (duplicado de `es/index.astro`).
4. **LangSwitcher**: añadir entrada para el nuevo locale.
5. **Validar**: comprobar que `astro check` pasa y que `npm run build` genera la carpeta `/<codigo>/index.html`.

## 8. Casos especiales del proyecto actual

- **`Skills`**: definido en el diccionario (`skills.title`, `skills.frontend`, etc.) pero **no** declarado en `NAV_ITEMS`. La sección "Tech stack" vive dentro de `About.astro`, no tiene anchor propio.
- **Proyectos con nombres propios**: `Projects.astro` mapea `projectImages` por nombre de proyecto (ambas traducciones apuntan al mismo seed de `picsum.photos`). Si renombras un proyecto, actualiza las claves ES y EN.
- **CV / links duros**: el CV (`/cv-nicolas-sanchez.pdf`), email, GitHub y LinkedIn están en `src/consts.ts` (`SITE`), no en los diccionarios, porque no cambian con el idioma.
